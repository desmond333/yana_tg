# План: Telegram Mini App для личного бренда «Яна Алфимова»

Статус: код готов к первому запуску (демо-контент). Инструкция запуска — `miniapp/LAUNCH.md`.
Расположение папки: `C:\Users\user\Desktop\anna-tg` (все Telegram-проекты).
Проект приложения: `C:\Users\user\Desktop\anna-tg\miniapp` (копия `react-fsd-starter`).
Бэкенд (Supabase: миграции и Edge Functions) лежит внутри репозитория: `miniapp/supabase`. Этот файл лежит вне репозитория и в git не коммитится.

## 1. Резюме

Mini App — мобильная витрина внутри Telegram: личный бренд маркетолога, каталог курсов и продуктов,
подкасты, Reels, бесплатные материалы и форма заявки. Открывается из публичного канала и через бота.

Главный сценарий:
пост в канале → кнопка «Открыть каталог» → Mini App → карточка продукта → «Оставить заявку» → заявка уходит Яне.

Дополнительные требования, которых не было в исходном промпте:

- Админка для одного человека (Яна сама загружает контент, без разработчика).
- Подкасты и Reels автоматически попадают в приложение из постов канала (по хештегам), с ботом-синхронизатором.
- Языки: русский и английский.
- Темы: светлая/тёмная/системная с синхронизацией с Telegram + 3 акцентные палитры (коралл / фиолет / изумруд).
- Приоритет проверенных лёгких библиотек, собственный велосипед только там, где библиотек нет.

## 2. Роли

| Роль                    | Что делает                                                        |
| ----------------------- | ----------------------------------------------------------------- |
| Гость (любой в Telegram) | Смотрит витрину, слушает подкасты в Telegram, оставляет заявку    |
| Яна (админ)            | Ведёт контент через админку в приложении, получает заявки         |
| Бот-синхронизатор       | Читает посты канала по хештегам, обновляет подкасты/Reels/материалы |
| Разработчик (я)         | Код, деплой, регулярные обновления                                |

Правила, которые соблюдаем без исключений:

- Публичный API слайса — единственный `index.ts`, только явные экспорты.
- Cross-слайсовые импорты — через `@/...`, внутри слайса — относительные.
- Слайсы одного слоя друг друга не импортируют.
- Legacy-каталоги (`components`, `hooks`, `store`, `utils`...) не создаём.
- Новые слайсы — только через `npm run gen:slice`.
- После изменений обновляем `PROJECT_MAP.md` и `README.md`.

Что удаляем из шаблона при копировании: `entities/counter`, DEV-примеры в `pages/dev-components` (страницу
переделаем под реальную дизайн-систему), демо-строки словарей.

## 5. Дизайн-система, темы, типографика

Визуальный язык: тёплый редакционный продукт, много воздуха, крупная типографика, скругления 16–24px,
лёгкие тени. Не инфобизнес и не шаблонный лендинг.

- Токены Tailwind 4 через `@theme`: цвета, радиусы, тени, отступы. Брендинг меняется в одном файле.
- Синхронизация с Telegram: `themeParams` маппятся в CSS-переменные; `data-theme` (light/dark/system)
  и `themeChanged` обрабатывает `ThemeSync`.
- Акценты (`data-accent`): `coral` (по умолчанию), `violet`, `emerald`. Акцент не зависит от темы Telegram,
  контраст каждого варианта проверяем на светлом и тёмном фоне.
- Типографика: минимальный основной текст 15–16px; кандидаты пар — Onest (текст) + Playfair Display (заголовки),
  альтернатива Unbounded. Шрифты self-host через Fontsource, без внешних CDN.
- Интерактив: высота целей ≥44px, видимый focus, `aria-label` у иконочных кнопок, семантическая разметка.
- Hover не используем как единственный индикатор — только touch.
- DEV-витрина `/dev/components` обязательна: каждый компонент во всех состояниях и темах (правило AGENTS.md).

## 7. Контент-пайплайн: хештеги и бот-синхронизатор

Как контент попадает в приложение:

1. Подкасты и Reels — автоматически из постов канала. Яна публикует как обычно, добавляет хештег.
2. Продукты и отзывы — через админку в приложении (меняются редко, нужны структурные поля: цена, программа, FAQ).
3. Бесплатные материалы — из постов канала по хештегу (карточка + ссылка на пост).

Теги по умолчанию (настраиваются в `shared/config`): `#подкаст`, `#рилс`, `#бесплатно`.
Бот добавляется админом канала и обрабатывает `channel_post` / `edited_channel_post`.

Разбор поста:

- Тип — по хештегу.
- Заголовок — первая непустая строка (обычно жирная) после тега.
- Описание — остальной текст; дополнительные хештеги становятся темами.
- Подкаст: длительность и обложка берутся из аудио/видео метаданных.
- Reels: длительность и превью из видео метаданных.
- Ссылка — `t.me/<канал>/<message_id>`; дедупликация по паре (channel_id, message_id), правки и удаления постов синхронизируются.

Ключевое решение по аудио: не копируем файлы к себе, «Слушать» открывает пост в Telegram —
играет нативный плеер со скоростью, фоном и без расходов на хранилище. Позже, если захочется
плеер внутри приложения, добавляется зеркалирование в R2 (ограничение Bot API — 20 МБ на файл, у подкастов
часто больше, это отдельный этап).

Ограничение Bot API: бот получает только новые посты, историю канала выкачать нельзя.
Старые выпуски Яна добавляет через админку или перепубликует с тегом.

Поток: пост в канале → webhook на Edge Function (grammY) → парсинг → upsert в Postgres → Mini App показывает.

## 8. Админка

Скрытый маршрут `/admin` внутри приложения — Яна всегда в Telegram, отдельное приложение не нужно.

- Доступ: `initData` → серверная валидация подписи + список разрешённых `tg_user_id` в БД. UI-флаг на фронте — только удобство, не безопасность.
- Функции MVP: продукты (CRUD, все поля, порядок), отзывы (CRUD), заявки (список, статусы new/в работе/закрыта),
  подкасты и Reels (правка заголовка/обложки, скрыть, переставить), черновик/публикация.
- Формы на тех же схемах RHF+Zod, что и публичная часть.
- Отдельные экраны вне нижней навигации; вход — через кнопку в профиле, видимую только админу.
- Запасной вариант: Supabase Studio — готовый табличный редактор, бесплатный и всегда доступен.
- Альтернативы (Directus, Payload, Strapi) отклонены: тяжело для одного человека и нашей задачи.

## 10. Интеграция с Telegram

Отдельный модуль `shared/lib/telegram/` + провайдер `app/bootstrap/TelegramProvider`:

- Безопасная инициализация SDK с fallback: вне Telegram приложение полностью работает (браузер, SSR-нет).
- `ready()` и `expand()` при старте; подписка на `viewportChanged`, CSS-переменная `--tg-viewport-height`.
- `themeParams` → CSS-переменные; реакция на смену темы Telegram «на лету».
- BackButton: на внутренних страницах показан, на «/» скрыт; клик — `navigate(-1)`; хук централизован в app-слое.
- MainButton: хук `useMainButton({ text, onClick, visible })`; на странице продукта и в форме заявки;
  корректный cleanup при уходе. Вне Telegram те же CTA рендерятся обычными кнопками.
- Внешние ссылки — `openLink` в Telegram, `window.open` вне; единая функция `openExternalLink`.
- Haptics на ключевых действиях (мягко, без навязчивости).
- Safe-area: `env(safe-area-inset-*)` + высота нижней навигации.
- Dev-панель (только DEV): isTelegram, user id, platform, colorScheme, версия.
- `initDataUnsafe` не используется для авторизации; `initData` передаётся на сервер и валидируется подписью
  (HMAC-SHA256), это зафиксировано в README и коде.

## 11. Локализация

- Язык по умолчанию: из Telegram `language_code`, иначе браузер, иначе ru. Выбор пользователя сохраняется и приоритетнее.

## 12. Бэкенд (этап 6+): выбор и схема

Сравнение вариантов бесплатного хостинга:

| Критерий            | Supabase (рекомендую)                          | Cloudflare D1 + R2 + Workers            |
| ------------------- | ---------------------------------------------- | --------------------------------------- |
| БД                  | Managed Postgres, 500 МБ free                  | SQLite (D1), 5 ГБ free                  |
| Готовая админка     | Да — Studio (таблицы, фильтры, права)          | Нет, всё писать самим                   |
| Файлы (обложки)     | Storage 1 ГБ free                              | R2 10 ГБ free, нет платы за трафик      |
| Функции             | Edge Functions (Deno) + grammY                 | Workers + Cron Triggers                 |
| Скорость запуска    | Высокая                                        | Средняя, больше кода                    |
| Риски free-тарифа   | Пауза проекта после ~7 дней простоя            | Щедрые лимиты                           |

Решение: MVP на Supabase (быстрее до результата + готовый Studio как запасная админка).
Аудио остаётся в Telegram, поэтому большой Storage не нужен; если появится свой плеер — добавим R2.

Схема БД: `products`, `podcasts`, `reels`, `reviews`, `leads`, `admins`, `settings` (профиль автора).
Тексты — `jsonb { ru, en }`. RLS: чтение только опубликованного, запись — только через Edge Functions
с валидацией `initData`. `anon`-ключ во фронте безопасен при RLS; service-ключ на фронт не попадает никогда.

Edge Functions: `tg-webhook` (приём постов канала, уведомления), `submit-lead` (валидация + запись + уведомление Яне),
`admin-content` (CRUD), `tg-file` (прокси обложек по `file_id`, т.к. ссылки Telegram протухают).
